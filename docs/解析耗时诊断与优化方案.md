## 2. 当前为什么慢

1. 六个智能体角色被展开为大量批次节点。评审智能体对每个原文批次都调用一次，普通说明文字也参与评审提取。
2. 条款输出较大，模型同时生成语义、来源引用、逐视图覆盖关系及关联字段。可由程序确定的信息占用输出时间，也增加格式出错机会。
3. 失败时第二次调用仍要求返回整个批次。一个引用或覆盖关系错误就可能让已正确提取的大量条款全部重写。
4. 当前存在阶段等待：全部条款和评审批次结束后才识别模板；模板完成后才进入绑定和复核。
5. 各任务分别控制并发，尚未形成模型服务级别的共享并发限制。相同文件的多个旧任务会增加总请求量。
6. 节点结果已经记录，但当前尚未实现基于成功节点的断点续跑。超时后的重新解析仍可能重复已完成工作。

## 3. 本轮已实现的基础修复

- 原文批次受控并行，默认 3 路，可通过 `PI_PARSE_WORKERS` 配置为 1–6；合并结果仍保持原文顺序。
- 增加 `PI_PARSE_TIMEOUT` 总时限，默认 1200 秒，并把剩余时限传到节点调用；请求结束或超时清理本次启动的 PI 子进程。
- 减少下游输入中可恢复的默认字段和来源元数据，持久化的解析契约仍保留完整字段。
- 强化响应主体、条件、响应阶段、证据来源及覆盖关系的提示词；本地校验失败反馈保留具体对象和视图标识，以便修正。
- 同一后端进程内，对相同工作区、项目、文件内容及运行参数的活动上传复用任务，并阻止同一任务重复启动。
- 保存逐节点状态、耗时、尝试和失败原因；前端显示耗时、完成节点、活动节点和失败节点。
- 解析存在审查问题时，前端展示待核查提示。

运行中的后端进程仍使用各自启动时的代码。重启后创建的新任务才会使用后续修改；本轮没有停止原任务，也没有把节点日志宣称为可恢复执行的检查点。

## 4. 后续实施顺序

### 第一步：降低条款失败与整批返工

状态：局部修补契约、本地问题收集与受限合并、编排接线及三个真实失败批次验证已完成。来源索引和引文核实继续使用本地只读来源工具；进一步压缩首次提取的来源表示及输出规模尚待实施。

把解析智能体的输出分成“模型判断的语义”和“工具生成的确定性结构”。来源索引、视图 ID、原文位置、可确定的关联标识由程序生成或验证；主体、条件、义务和响应方式仍由 PI 判断，未知信息保留待核查状态。

校验器应返回结构化的问题列表，包括对象标识、字段路径、问题类型和可使用的来源视图。保留首次输出及已通过对象，第二次调用只提交需要修正的对象、遗漏视图或关联关系。模型返回受约束的修补结果，程序合并后重新执行完整契约、来源和覆盖校验。

合法 JSON 且仅有字段或关联错误时采用局部修补；无法解析、关键结构缺失或模型没有正常返回时，才允许一次完整重试。语义事实错误不能通过补默认值掩盖。

验收重点：首次失败比例、修补输入输出大小、修补耗时、最终完整覆盖率。先用已失败批次与高密度技术条款批次验证，再测整份文件。

### 第二步：按章节和依赖编排

本地工具先完整读取标题、段落、表格及格式区域，建立章节索引。PI 只处理结构分类中的不确定项。每个原文视图都应有路由结果；不能只依据关键词跳过一般条款中的否决条件、证明要求或澄清义务。

- 条款提取按资格、商务、技术和合同等区域执行，保留采购包、阶段及跨章节上下文。
- 评审智能体只处理评审方法、评分表、否决条件和相关引用所在区域，避免对全部批次重复空提取；路由不确定区域进入补查。
- 模板智能体在本地结构就绪后读取投标格式区域，可与条款及评审提取并行。
- 绑定任务在对应条款和模板就绪后启动，复核任务在对应依赖就绪后启动，避免全阶段屏障。
- 本地审计覆盖全部来源、要求、证据和关联关系；语义复核聚焦高风险、冲突及不确定内容，并保留全局交叉检查。

验收重点：实际模型调用次数、各类节点的等待与执行时间、端到端耗时；同时检查被路由为背景的区域是否遗漏投标义务。

### 第三步：原模板和响应表由工具执行

保留原 DOCX 模板片段及 OOXML 复制能力。程序承担原表定位、列结构保留、已确认规则下的行绑定、已知项目和企业字段填充、证明材料插入及输出校验。

PI 决定章节和模板用途、条款响应内容、歧义绑定以及需要补充的证明材料。只有未确定的对应关系调用模型，不让每个批次重复发送所有原表。不得为了提速把原响应表改造成自由生成表格。

验收重点：原模板版式、响应行对应关系、字段来源及证明材料完整性，确保既有写作和导出能力继续可用。

### 第四步：共享限流、缓存和续跑

在服务层统一限制模型并发，控制多个任务共同占用的请求数；依据真实排队与失败率调整并发。

检查点与缓存键至少包含工作区、源文件哈希、节点输入哈希、契约版本、提示词版本、工具版本及模型配置标识。只复用兼容且已通过校验的节点；输入或模板改变时，下游缓存应失效。

恢复时重新验证源文件及成功节点，执行失败、未完成或失效节点。前端展示可恢复状态及具体失败阶段，避免用户通过重复上传尝试继续。

验收重点：中断恢复不重复已完成节点，参数变更不会复用过期结果，多个任务不会超出共享并发上限。
