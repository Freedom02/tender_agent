# 招投标智能体整体开发计划

## 1. 文档目的

本文档用于说明招投标智能体项目接下来的整体开发流程、阶段目标、模块拆分、交付物和验收标准，便于团队成员统一理解开发顺序和协作边界。

本项目的核心目标不是“自动替代人工投标”，而是帮助业务员更快完成以下工作：

1. 找项目。
2. 看公告资格。
3. 看招标文件。
4. 判断是否值得投标。
5. 生成可审核的响应文件底稿。

## 2. 项目现状

当前 Demo 已具备以下基础能力：

- 招标项目检索和监控
- 公开网站基础抓取
- 招标文件导入和文本解析
- 企业资料库保存
- 基础匹配和评分
- 标书草稿生成
- 站内提醒和企业微信测试

当前尚未完整实现的能力包括：

- OCR 识别
- Excel 和图片解析
- 企业资料结构化抽取
- 条款级证据管理
- 多公司隔离
- 真正的三层匹配引擎

## 3. 总体目标

项目后续开发要逐步完成一条完整链路：

```text
企业资料上传
  -> 企业资料解析
  -> 项目搜索
  -> 公告粗匹配
  -> 招标文件详细匹配
  -> 评分和投标建议
  -> 响应文件底稿生成
```

系统输出只做辅助判断，不替代人工、法务、财务或项目负责人最终决策。

## 4. 开发原则

1. 先做结构化，再做智能化。
2. 先做公开网站和可控数据源，再做需要登录的网站。
3. 先做可解释结果，再做复杂评分模型。
4. 关键材料不足时，优先输出“待确认”，不要硬判通过。
5. 所有结论必须尽量回溯到原文证据。
6. 公司资料必须隔离，不能混用。

## 5. 整体开发流程

### 5.1 企业资料入库

用户上传公司资料后，系统需要完成：

- 文件保存
- 文件类型识别
- 文本提取
- OCR 识别
- 结构化字段抽取
- 文档分类
- 人工确认
- 证据索引建立

输出结果应支持后续匹配使用，例如：

- 营业执照
- 人力资源服务许可证
- 劳务派遣经营许可证
- 类似业绩
- 项目经理信息
- 人员证书
- 服务区域

### 5.2 项目搜索

系统根据企业配置的关键词、服务方向、地区和排除词，持续搜索公开招标项目。

搜索范围建议分为两类：

- 公开网站
- 后续可接入的登录网站

第一版优先支持公开网站，暂不做自动登录、验证码处理和付费文件自动获取。

### 5.3 公告粗匹配

公告粗匹配目标是判断“这个项目值不值得继续看”。

主要判断维度：

- 服务类型是否匹配
- 关键词是否命中
- 地区是否匹配
- 是否属于公司业务方向
- 是否存在明显排除项
- 是否已经过截止时间

粗匹配输出应包括：

- 相关性分
- 命中理由
- 排除原因
- 是否进入下一层分析

### 5.4 招标文件详细匹配

用户自行获取招标文件后上传，系统对文件做条款级判断。

重点拆解维度：

- 资格条款
- 商务条款
- 技术条款
- 人员要求
- 业绩要求
- 服务方案
- 质量保障
- 应急预案
- 报价要求
- 响应格式
- 否决项

输出应包括：

- 每条条款的状态
- 证据引用
- 页码定位
- 风险等级
- 待确认内容
- 缺口清单

### 5.5 评分和投标建议

系统需要根据匹配结果输出建议，帮助业务员快速决策。

建议输出形式：

- 建议参与
- 建议补充材料后复核
- 人工重点评估
- 不建议参与

评分不应只看满足条目数量，而应结合：

- 相关性
- 资格满足度
- 详细条款匹配度
- 风险扣分

### 5.6 响应文件生成

在业务员确认投标后，系统生成响应文件底稿。

底稿能力包括：

- 章节结构生成
- 模板套用
- 企业证据引用
- 缺失项提示
- 导出 Markdown、Word、JSON 等格式

## 6. 分阶段实施计划

### 阶段 0：项目整理和基础稳定

目标：让团队可以稳定协作、快速上手。

主要任务：

- 固化目录结构和文件职责
- 统一前后端启动方式
- 清理重复页面和冗余逻辑
- 补充开发文档和接口说明
- 统一环境变量和配置文件规范

验收标准：

- 新成员可按文档启动项目
- 前后端可正常运行
- 目录和职责清晰

### 阶段 1：企业资料库解析

目标：把“上传资料”变成“可用于匹配的结构化资料”。

主要任务：

- 支持 PDF、Word、Excel、图片、扫描件上传
- 接入 OCR
- 抽取企业基础信息
- 抽取证照、业绩、人员、服务区域
- 记录文件来源、页码、哈希和版本
- 增加人工确认机制

验收标准：

- 上传资料后能生成结构化字段
- 重要字段可追溯到证据
- 解析结果支持修订和复核

### 阶段 2：第一层匹配，项目相关性判断

目标：先判断项目是不是值得继续看。

主要任务：

- 设计业务画像
- 配置服务类型和同义词规则
- 配置地区规则
- 配置关键词和排除词
- 输出相关性分和命中理由

验收标准：

- 搜到的项目可自动区分高相关、一般相关、不相关
- 结果可解释、可复核

### 阶段 3：第二层匹配，公告资格判断

目标：根据公告正文判断公司是否具备基础报名资格。

主要任务：

- 抽取资格条款
- 识别证照、业绩、人员、地域等要求
- 识别硬性否决项
- 绑定企业资料证据
- 生成缺失材料清单

验收标准：

- 每条资格要求都有状态
- 关键否决项可单独标出
- 信息不足时不误判为满足

### 阶段 4：第三层匹配，招标文件详细判断

目标：对完整招标文件做条款级匹配。

主要任务：

- 多文件上传
- OCR 和目录识别
- 条款拆解
- 企业证据检索
- 页码和原文定位
- 风险和缺口分析

验收标准：

- 条款可逐条追溯
- 结论有证据支撑
- 可输出高风险和待确认项

### 阶段 5：评分和投标建议

目标：让系统给出清晰的决策辅助。

主要任务：

- 建立评分权重
- 建立硬性否决规则
- 建立风险扣分逻辑
- 建立可解释输出格式

验收标准：

- 评分结果可解释
- 建议结果可复核
- 不能把硬性不满足项目误判成可投

### 阶段 6：响应文件生成

目标：根据已确认材料生成可审核底稿。

主要任务：

- 模板库
- 章节映射
- 证据自动引用
- 缺失项提示
- 导出和版本控制

验收标准：

- 可生成可编辑底稿
- 关键缺失项不会被隐藏
- 导出结果可审阅

### 阶段 7：多公司和正式化

目标：支持多公司独立使用，进入更接近生产的形态。

主要任务：

- 引入公司 ID
- 数据隔离
- 用户认证和权限控制
- 审计日志
- 数据库存储
- 对象存储
- 任务队列和重试

验收标准：

- 不同公司数据互相隔离
- 权限和审计完整
- 系统可稳定扩展

## 7. 模块拆分建议

### 7.1 企业资料库模块

负责：

- 上传
- 解析
- 分类
- 证据索引
- 人工确认

### 7.2 招标搜索模块

负责：

- 关键词配置
- 公开网站搜索
- 定时监控
- 去重
- 新项目提醒

### 7.3 匹配引擎模块

负责：

- 第一层相关性
- 第二层公告资格
- 第三层详细条款匹配
- 评分和建议

### 7.4 工作台模块

负责：

- 匹配结果查看
- 草稿编辑
- 响应文件生成

### 7.5 通知模块

负责：

- 站内提醒
- 企业微信通知
- 未来可扩展其他通知渠道

## 8. 数据流建议

```text
上传公司资料
  -> 资料解析
  -> 资料入库
  -> 建立证据索引

搜索招标项目
  -> 公告抓取
  -> 公告粗匹配
  -> 生成待分析项目

上传招标文件
  -> 文件解析
  -> 条款拆解
  -> 企业证据比对
  -> 评分和建议
  -> 生成响应底稿
```

## 9. 近期优先级

建议近期按以下顺序推进：

1. 企业资料库解析
2. 公告粗匹配
3. 招标文件详细匹配
4. 评分和建议
5. 响应文件生成
6. 多公司和权限隔离

原因是：没有结构化企业资料，后面的所有匹配都会不稳。

## 10. 风险与边界

### 10.1 暂不开发

第一版不做：

- 自动登录
- 验证码处理
- 付费文件自动下载
- 自动报名
- 自动投标
- 自动报价
- 直接提交正式标书

### 10.2 主要风险

- 资料格式复杂，解析效果不稳定
- 不同网站结构差异大
- 证据页码和有效期难以统一
- 评分规则容易被误用为最终结论
- 多公司隔离在后期改造成本较高

### 10.3 风险应对

- 先定义统一数据结构
- 先做可解释结果
- 保留原文证据
- 所有结论都允许人工覆核
- 尽早预留 `company_id`

## 11. 协作约定

1. 变更前先看文档和当前模块职责。
2. 新增字段要同步更新前后端类型和接口说明。
3. 不要把 Demo 逻辑直接当生产逻辑。
4. 不要把临时配置文件提交到 Git。
5. 关键改动要写清楚影响范围和验收方式。

## 12. 交付目标

第一阶段理想交付物：

- 可上传公司资料
- 可解析并保存结构化字段
- 可搜索公开招标项目
- 可自动做粗匹配
- 可判断是否值得继续看
- 可进入详细分析工作台

第二阶段理想交付物：

- 可做条款级详细匹配
- 可输出证据和缺口
- 可给出可信的投标建议

第三阶段理想交付物：

- 可生成可审核响应文件底稿
- 可支持多公司隔离
- 可进入正式协作开发阶段

## 13. 结语

本项目最重要的不是“多聪明”，而是“可解释、可追溯、可协作”。  
后续所有开发都应围绕资料、证据、规则和人工确认这四个核心继续推进。
